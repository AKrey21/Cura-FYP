# System latency - per-stage and end-to-end (2026-06-11)

**Harness:** `python -m cura eval-latency` (`cura/eval/latency.py`) - N timed
runs after one untimed warm-up (so model loading is reported as cold start,
not folded into steady-state stats); per-stage seconds come from the
orchestrator's RunReport, aggregated as mean / p95 / min / max.

**Environment:** AMD Ryzen 7 7800X3D (8C), 31 GB RAM, Windows 11,
Python 3.13.3, CPU-only inference (no GPU used by torch).

## Reading

- The light stack's whole pipeline is ~13 ms of compute on the fixture -
  end-to-end briefing time is **entirely ingestion/network bound**, which is
  why `cura serve` builds editions in the background and serves
  stale-while-revalidate.
- The stretch stack multiplies compute ~1600× on CPU, all of it in BART
  (~1.7 s per summary pass; every cluster gets a tight + a detail pass).
  RoBERTa stance adds only ~0.4 s total. This quantifies the earlier
  decision (2026-06-11 summary benchmark) to keep TextRank as the default
  summariser and offer BART as an opt-in: on this hardware BART would add
  ~2–3.5 s per analysed cluster to every edition build.
- Numbers are single-machine, CPU-only; re-run the harness on the demo
  machine before quoting them in the report.
